# Статус проєкту TripFlow

## Етапи 6–7: функціональність, тестування та якість

Звіт станом на 13.11.2026 (гілка `main`, PR #67–#83).

### Що зроблено

**Етап 6: ітеративна реалізація**

| Модуль | Хто | Результат |
|---|---|---|
| Поїздки та навігація | Артем | Список поїздок картками, створення й видалення, статус за датами («Заплановано / У процесі / Завершено»), фільтр «Усі / Заплановані / Завершені», вікно поїздки з вкладками й повернення до списку (PR #69) |
| Розклад | Ніка | Генерація днів за датами поїздки, додавання, редагування й видалення подій, сортування за часом, перевірка дати в межах поїздки (PR #67, #71) |
| Бюджет | Ася | Додавання й видалення витрат, загальна сума, залишок і відсоток використання, ProgressBar з конвертером: зелений → жовтий від 80% → червоний при перевитраті (PR #68) |
| Чек-лист та обмін даними | Остап | 5 категорій речей, позначка «спаковано» зі збереженням у БД, прогрес по категоріях і загальний; експорт і імпорт поїздки у JSON з перевіркою структури (PR #70, #77) |

Спільне: шари UI → BLL → DAL → LocalDB, DI в `App.xaml.cs`, журналювання через Serilog, помилки показуються в інтерфейсі без аварійного завершення.

**Етап 7: тестування та якість**

- Модульні тести BLL (xUnit + Moq, без бази даних):
  - `TripServiceTests`: валідація кожного поля, статус для 5 дат;
  - `ItineraryServiceTests`: дні, сортування, дата поза поїздкою;
  - `BudgetServiceTests`: додавання, валідація суми й категорії, підрахунок, крайові випадки (рівно 100%, поріг 80%, суми 0,01 і максимальна, видалення останньої витрати);
  - `DataTransferServiceTests`: експорт, імпорт, пошкоджений файл.
- Інтеграційні тести репозиторіїв на LocalDB (PR #83).
- Рефакторинг:
  - `PackingService` повертає `OperationResult` замість винятків, відсоток зборів перенесено в сервіс (PR #80, #81);
  - валідацію поїздки перенесено з форми в `TripService` (PR #82).

### Що лишилося

- PDF-звіт поїздки (`ReportService`), кнопка «Експорт .pdf» поки неактивна.
- На картці поїздки бюджет показує «0 ₴ / …»: треба підставити фактичні витрати з `BudgetService`.
- Етап 8: автоматичне збирання й запуск тестів у GitHub Actions.
- Оновити вайрфрейми в `UI/`, щоб вони збігалися з фінальною програмою.

### Проблеми та як вирішили

- **Конфлікти злиття** у спільних файлах (`App.xaml.cs`, вікно поїздки), коли кілька PR були відкриті одночасно. Рішення: перед злиттям оновлюємо гілку з `main` і перевіряємо збірку.
- **Різні версії .NET** (проєкти були на .NET 9, у частини команди лише SDK 8). Рішення: усі проєкти переведено на .NET 8.
- **LocalDB не встановлено** на одному з комп'ютерів, програма не запускалась. Рішення: встановили компонент «SQL Server Express LocalDB» через Visual Studio Installer.
- **Розбіжності між документами**: формат експорту (.txt проти JSON/PDF). Рішення: виправлено в `PRIORITIZATION.md`, далі перевіряємо `USER_STORIES.md` і `SCENARIOS.md`.
