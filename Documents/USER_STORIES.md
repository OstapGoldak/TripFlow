# User Stories та критерії приймання (TripFlow)

## 1. Керування подорожами

### User Story 1: Створення нової подорожі
* **Формулювання:** Як мандрівник, я хочу створити нову подорож, вказавши назву, місто/країну, дати початку й закінчення та запланований бюджет, щоб розпочати планування поїздки.
* **Acceptance Criteria (AC):**
  1. Користувач може відкрити форму створення подорожі через головне меню застосунку.
  2. Обов'язкові поля: *Назва*, *Місто/Країна*, *Дата початку*, *Дата завершення*, *Планований бюджет*.
  3. **Валідація:** Дата завершення не може бути ранішою за дату початку, а бюджет не може бути від'ємним.
  4. Після збереження подорож записується до локальної бази даних MS SQL Server і з'являється у списку.

### User Story 2: Фільтрація та перегляд списку подорожей
* **Формулювання:** Як мандрівник, я хочу переглядати свої поїздки у вигляді карток і фільтрувати їх за статусом («Усі», «Заплановані», «Завершені»), щоб швидко знаходити потрібну інформацію.
* **Acceptance Criteria (AC):**
  1. Головний екран відображає список поїздок у вигляді карток із назвою, локацією, датами та бюджетом.
  2. Панель фільтрів містить елементи: «Усі», «Заплановані», «Завершені».
  3. Список миттєво оновлюється при перемиканні фільтра відповідно до поточних дат.

---

## 2. Розклад та активності дня

### User Story 3: Автоматична генерація днів та додавання активностей
* **Формулювання:** Як мандрівник, я хочу, щоб система автоматично сформувала список днів за датами подорожі та дозволяла додавати активності до кожного дня, щоб детально розписати свій маршрут.
* **Acceptance Criteria (AC):**
  1. Система автоматично генерує послідовність днів відповідно до дат початку й закінчення поїздки.
  2. До кожного дня можна додати активність із полями: *Час*, *Назва*, *Локація*, *Орієнтовна вартість*, *Примітка*.
  3. Усі події всередині дня **автоматично сортуються хронологічно** за часом початку.
  4. Можливість редагування та видалення активностей з оновленням бази даних.

---

## 3. Фінансовий облік

### User Story 4: Внесення витрат та контроль бюджету
* **Формулювання:** Як мандрівник, я хочу вносити витрати із зазначенням категорії та суми, щоб бачити залишок коштів та контролювати перевитрати через візуальний індикатор.
* **Acceptance Criteria (AC):**
  1. Користувач додає витрату із зазначенням дати, категорії (*Житло, Транспорт, Їжа тощо*), суми та опису.
  2. **Валідація:** Сума витрати не може бути від'ємною або нульовою.
  3. Система автоматично рахує загальну витрачену суму та поточний залишок.
  4. **Візуальний індикатор (ProgressBar):** Показує використання коштів і підсвічується **червоним кольором** у разі перевитрати бюджету.
  5. Видалення помилкового запису миттєво оновлює залишок і шкалу прогресу.

---

## 4. Чек-листи спорядження

### User Story 5: Керування категоріями та зборами речей
* **Формулювання:** Як мандрівник, я хочу додавати речі до 5 фіксованих категорій і відзначати їх чекбоксами, щоб нічого не забути перед поїздкою та бачити прогрес зборів у відсотках.
* **Acceptance Criteria (AC):**
  1. Доступні 5 базових категорій: *«Документи»*, *«Одяг»*, *«Техніка»*, *«Аптечка»*, *«Інше»*.
  2. Користувач може додавати нові речі до категорій або видаляти їх.
  3. Чекбокси спакованих речей зберігають свій стан у локальній базі даних.
  4. Інтерфейс виводить загальний **прогрес зборів у відсотках**, що перераховується при зміні статусів речей.

---

## 5. Експорт даних

### User Story 6: Експорт плану поїздки та розкладу у файл
* **Формулювання:** Як мандрівник, я хочу експортувати структурований розклад та список речей у локальний текстовий файл (`.txt`), щоб мати до них доступ офлайн на телефоні або роздрукувати перед виїздом.
* **Acceptance Criteria (AC):**
  1. Наявна кнопка «Експортувати дані» в меню поїздки.
  2. Виклик стандартного діалогового вікна збереження файлу Windows (Save File Dialog).
  3. Генерація `.txt` файлу зі структурованою інформацією про подорож, розклад, витрати та чек-лист.
  4. Швидке збереження файлу на локальний диск без зависання застосунку.
