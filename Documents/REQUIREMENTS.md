# Специфікація вимог до застосунку TripFlow

## 1. Нефункціональні вимоги
* **Платформа:** десктопний застосунок для ОС Windows (WPF, .NET 8).
* **Збереження даних:** локальна база даних MS SQL Server (LocalDB); файл бази зберігається на комп'ютері користувача.
* **Автономність:** працездатність без підключення до мережі.
* **Надійність і валідація:** обов'язкова перевірка вхідних даних (бюджет і суми витрат не можуть бути від'ємними; дата завершення не може бути ранішою за дату початку). Програма перехоплює помилки без аварійного завершення роботи.


## 2. Функціональні вимоги

### Керування подорожами
* Створення нової подорожі (назва, місто/країна, дати початку й закінчення, запланований бюджет).
* Перегляд списку поїздок у вигляді карток із можливістю фільтрації («Усі», «Заплановані», «Завершені»).
* Редагування параметрів поїздки та можливість її видалення.

### Розклад та активності дня
* Автоматична генерація переліку днів відповідно до обраних дат поїздки.
* Додавання активностей до конкретного дня (час, назва, локація, орієнтовна вартість, текстова примітка).
* Автоматичне хронологічне сортування активностей у межах обраного дня.
* Редагування та видалення подій із розкладу.

### Фінансовий облік
* Внесення витрат із зазначенням дати, суми, категорії (житло, транспорт, їжа тощо) та опису.
* Автоматичний підрахунок загальної витраченої суми та поточного залишку від бюджету.
* Візуальний індикатор (ProgressBar) використання коштів із підсвічуванням червоним кольором у разі перевитрати.
* Видалення помилково внесеного запису витрати з миттєвим перерахунком залишку.

### Чек-листи спорядження
* Додавання речей із прив'язкою до 5 категорій: «Документи», «Одяг», «Техніка», «Аптечка», «Інше».
* Позначення спакованих позицій чекбоксами зі збереженням статусу в базі даних.
* Відображення прогресу зборів речей у відсотках.
* Можливість видалення речей зі списку.

### Експорт та імпорт даних
* Експорт подорожі (JSON):** вивантаження обраної подорожі з усіма прив'язаними даними (розклад, витрати, чек-листи) у файл формату `.json` для перенесення на інший пристрій або створення резервної копії.
* Імпорт подорожі (JSON):** завантаження раніше експортованого `.json` файлу в застосунок на іншому комп'ютері, валідація структури та збереження даних у локальну БД для подальшого редагування.

### Формування звітів
* Генерація PDF-звіту:** формування підсумкового документа (`.pdf`) зведеної інформації про поїздку (дати, статус бюджету, розклад активностей і стан спорядження) для друку, надсилання попутникам або перегляду поза програмою.
